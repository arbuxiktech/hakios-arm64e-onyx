## Kernel preparation and validation

The kernel source is in `/home/arbuxik/ios-26-onyx-build/xnu12377` in WSL.
`tools/prepare-kernel.py` reads the Dada patch from Git objects, avoiding Windows
CRLF conversion. It adds a passive Onyx touch diagnostic thread and removes the
unrelated Redwood Goodix/FocalTech object from the Onyx build. No firmware for
another touchscreen is embedded or substituted.

The reference's legacy transport uses allocator APIs removed in XNU 12377.
Those transport sections are excluded at compile time in this initial build.
The passive diagnostics object compiled successfully with the generated XNU
flags. Its undefined symbols contain no MMIO, GPIO, SPI, SMMU or DMA functions.
This is a diagnostic milestone; it cannot produce touch input yet.

Private build dependencies are under `/home/arbuxik/ios-26-onyx-build/base`.
Clang 19 packages were extracted into `llvm19` without system installation.
Support libraries now compile after fixing the Linux environment script and
using opaque thread APIs in the old firehose support object.

The full kernel build was attempted and **did not link**. Remaining failures:

- The Linux IIG shim supplies no matching `IOExtensiblePaniclog` generated
  interface, producing missing method declarations and class-layout errors.
  The upstream shim itself states that matching iOS 26 interface generation
  needs the real IIG from an appropriate Xcode installation.
- Some PAC-specific source paths do not compile with the current upstream
  Clang configuration, including `vm_dyld_pager.c` and `kern_exec.c`.
  PAC must be preserved and validated, not removed to silence these failures.

The build logs are `out/kernel-build.log` and `out/kernel-stage2.log`.
`out/touch-compile.json` records the successful diagnostic-object build.
That Linux attempt did not produce a linked kernel, boot payload or flash image.

`ipsw` utility. The OS root filesystem and arm64e dyld cache set were extracted.
Four relative links rejected by 7-Zip were restored only after their paths and
targets were verified to remain inside the extraction root.

SystemOS filesystem extraction is complete. A private official 7-Zip 26.06
build could not decode 1597 files, including actual Mach-O binaries. Those files
were recovered using `ipsw extract --files`. Every recovered file was checked
against its uncompressed size in the archive metadata before being copied into
the SystemOS tree. The remaining `libstdc++.dylib` relative link was restored
after verifying that its target chain remains inside that tree. The completion
record is `ios26/cryptex/.onyx-extraction-complete` in the WSL build folder.

System/cryptex/cache preparation is not APFS image assembly. No iOS system
image has been installed on the phone. Stock Android images are restoration
inputs and hardware references; they do not replace a backup of the installed
OxygenOS port or its encrypted userdata.
